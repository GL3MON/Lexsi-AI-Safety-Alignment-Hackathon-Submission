## Abstract

Small open models can emit syntactically valid tool calls, but they fail as agents: they invent missing emails and IDs, corrupt identifiers when copying, repeat failing calls and claim success before a tool confirms it. We treat this as a self-healing problem: the model should notice a failed call and repair it from the tool’s feedback. We adapt Tiny Aya Global into a retail customer-service agent for τ²-bench through staged training. Function-calling SFT teaches the interface; a 700-conversation synthetic retail corpus, generated by a Qwen3.5-4B teacher inside isolated executable retail worlds, teaches workflows and recovery: each recovery example contains a real failed call and its real error, with the faulty call loss-masked and only the repair supervised. We then run online GRPO with verifiable rewards, first on complete τ² tasks, then on short 1–4 action goals. Short RL gives measurable local gains (1/9 → 4/9; 86/114 → 89/114), and a controlled SFT shows the ask-versus-call decision is learnable and transfers to new identities. However, every compared checkpoint scores 0/3 on selected native τ² validation tasks. We also report negative results (weighted SFT, DPO) and a reward-hacking audit in which a successful-call bonus rewarded irrelevant reads.

## 1. Problem statement and approach

**Why this problem.** Retail support is high-volume and tool-driven. A model small enough to run on a 6 GB GPU would make it cheap, but only if it is reliable: it must ask instead of guess, copy arguments exactly, pick the right operation, and recover when a call fails.

**Observed failure modes (pre-training probes).** Calling tools before required inputs are known; fabricating emails, user IDs and ZIPs (e.g. John Doe 12345); malformed JSON or wrong argument keys; repeating a failed call; choosing an operation that does not fit the order state; and writing a fake tool response plus “success” in the same turn (base model, task 38: invented order `#W0000000`; the real environment returned `Order not found`).

**Hypotheses.**

- **H1:** Supervising only the repair after a real error teaches recovery without teaching the error.
- **H2:** Short, fully verifiable episodes give a usable RL signal where complete tasks give none.
- **H3:** Outcome-based rewards without per-call bonuses resist reward hacking.

**Related work.** τ-bench / τ²-bench [1] (environment and evaluation); GRPO [2]; DPO [3]; LoRA [4]; Hermes function-calling data [5]; AlignTune [6].

## 2. Hackathon kits used

- **AlignTune:** all SFT stages (LoRA, assistant-only loss masks), online GRPO through its RL integration, and a custom trainer extension for DPO and for category-weighted per-example SFT loss.
- **CuratorKIT, AgentTune, SafeTune, CircuitKIT, AuditKIT:** not used in this submission. Data filtering and auditing were done with our own deterministic checks (Section 4).

**How it connects.** Synthetic data generator (Qwen teacher + executable retail world) → AlignTune SFT → AlignTune GRPO in the τ² retail environment with our verifiers as reward → greedy evaluation on fixed held-out cases and native τ² tasks.

**Generation and filtering.** Each scenario is an isolated synthetic retail database (customers, orders, products, payment methods). Separate customer and agent actors talk, and every tool call is executed for real. Checks: speaker/perspective and customer-echo detection, JSON and schema validation, execution against the database, auth/ownership/confirmation and goal-state checks, calculator operand provenance, and full-template token counts with label-mask audits. A prose audit flagged 117 conversations with unsupported claims in assistant text (their tool calls were correct); all 700 were kept, a known limitation.

**Short RL scenario bank.** 3,000 scenarios, 30 goal families, 100 synthetic worlds; split 2,400 / 300 / 300 with whole worlds disjoint across splits and no duplicate contexts (leak check: exact match on world/customer identity and public context). Covers all 15 retail tools.

**Benchmarks.** τ²-bench retail, project partitions: 22 RL tasks, 10 validation, 40 test (test untouched). Development sets: 9 held-out mini-scenarios; 30/90/114-case greedy sets from held-out worlds.

## 5. Metrics

All higher is better unless noted.

- Native τ² task success (database + action + communication checks).
- Short-goal success on fixed held-out greedy cases, also split by family (clarification vs. other = retention check).
- Initial clarification accuracy vs. complete clarification subgoal (asking is not enough; the agent must use the reply).
- Malformed-call rate by turn depth and failure streaks (both lower is better).

**Judge.** Short-goal metrics use deterministic route and state-hash verifiers. Native τ² NL assertions use a frozen Qwen judge; agreement with human labels was not measured.

## 6. Method

**SFT with recovery masking.** Recovery examples are built by taking a valid intended call, applying one controlled corruption, executing it to obtain a real error (with no database mutation), then executing the model’s correction. The corrupted call stays visible but is masked out of the loss:

$$
\mathcal{L}_{\mathrm{SFT}}=-\frac{1}{\sum_t m_t}\sum_t m_t\log\pi_\theta(y_t\mid x,y_{<t}),
$$

where $m_t=0$ for system, user, tool tokens and injected errors.

**Reward for complete tasks.** Sum of evaluated τ² criteria $c_j$ minus argument-grounding and failure-streak penalties:

$$
R(\tau)=\sum_{j\in C(\tau)}c_j-0.25\frac{I}{\max(1,N)}-\sum_{t\in F(\tau)}\min\bigl(1,0.25\max(0,s_t-1)\bigr),
$$

where $I$ counts ungrounded or invalid calls among $N$ attempts and $s_t$ is the consecutive-failure streak. The first failure is free, so a single error followed by a fix is not punished. Short-goal RL uses +1 for completing the goal and −1 otherwise.

**GRPO.** Group-relative advantages $\hat{A}_i=\frac{R_i-\mathrm{mean}(R)}{\mathrm{std}(R)+\epsilon}$; clipped ratio objective with KL to the reference policy. Only newly sampled assistant actions receive policy loss.

## 7. Results

**Headline: the retail pipeline teaches the model to heal itself**

| 114-case held-out retail set | Base Tiny Aya | FC-SFT (start) | Ckpt-7 (final) |
|---|---:|---:|---:|
| Recovery after a failed tool call | 0/9 | 2/9 | 9/9 |
| Use the customer’s reply after a clarification | 13/24 | 2/24 | 24/24 |
| Opening clarification | 1/24 | 0/24 | 13/24 |
| Other retail skills | 19/66 | 22/66 | 45/66 |
| **Total** | **33/114** | **24/114** | **82/114** |

*Table 3: Same cases, prompts, template and verifier (real τ² retail tools + expected database state); greedy, 4-bit.*

FC-SFT = function-calling SFT, the start of retail training. Recovery = malformed JSON, unknown tool or wrong argument. Ckpt-7 is several stages past FC-SFT (retail SFT, clarification SFT, short RL), so this measures the whole retail pipeline; RL alone is in Finding 1. In BF16, ckpt-7 scores 89/114.

Same cases, prompts, chat template and verifier (real τ² retail tools + expected database state), greedy decoding, 4-bit inference. The final model is several stages past the function-calling SFT (retail SFT, clarification SFT, short RL), so this measures the whole retail pipeline; RL alone is measured in Finding 1. In BF16, ckpt-7 scores 89/114 (vs. 82/114 here in 4-bit).

After one real tool error, the final model produced the correct repaired call in every recovery case. The starting model usually described the error instead of fixing it: “The correct tool call is get_order_details with the argument order_id. Please provide the order ID” (an ID it already had), or it escalated to a human agent.

### Finding 1: short verifiable RL improves local decisions

| Held-out mini-scenario (validation identities, tasks 69/34/63) | Before RL | After RL (ckpt 8) |
|---|---:|---:|
| Email lookup | 1/3 | 3/3 |
| Missing-ZIP clarification + lookup | 0/3 | 1/3 |
| Authentication → order status | 0/3 | 0/3 |
| **Total** | **1/9** | **4/9** |

| Paired greedy dev set (114 cases, 3 held-out worlds) | Pilot ckpt-6 | Continuation ckpt-7 |
|---|---:|---:|
| Use supplied information after a clarification reply | 22/24 | 24/24 |
| Complete an opening clarification scenario | 14/24 | 15/24 |
| Other retail skills (retention) | 50/66 | 50/66 |
| **Total** | **86/114** | **89/114** |
| Native τ² validation tasks 69, 34, 63 | 0/3 | 0/3 |

Three cases flipped to success with no lost passes. For example, after receiving ZIP 19353, the continuation combined it with the known name and called the lookup instead of asking for an email.

### Finding 2: the ask-vs-call decision is learnable, but asking ≠ finishing

A controlled SFT on 40 matched examples (each “missing field” prompt paired with the same prompt plus that field) raised matched-pair accuracy from 1/20 to 20/20 on both training and fresh-identity pairs, while supplied-field calls stayed at 20/20. On the broader 90-case set, correct first clarification rose 6/24 → 21/24, but complete clarification subgoals stayed at 5/24 and overall went 57 → 54/90: the model asked correctly, then failed to use the reply. Clarification-reply RL (Finding 1, second table) was designed to fix this.

### Finding 3: a positive call bonus was a reward hack

In the first native τ² RL group, all 16 rollouts had native reward 0, yet the top-advantage rollout earned +0.389 purely from seven distinct successful reads (auth, account, order, product) without performing the requested change. We removed the standalone call bonus; positive reward now comes only from task checks. Under the revised reward this rollout scores 0.

### What did not work

- **Complete-task RL from scratch:** task 103 group, 8/8 rollouts with native reward 0; advantages only ranked failures.
- **Expanded 3,000-scenario RL:** 480 rollouts, 28 updates; validation unchanged at 17/30.
- **Category-weighted SFT:** clarification 5 → 10/24 but other families 52 → 45/66 (asked unneeded questions); overall 57 → 55/90.
- **DPO:** held-out preference accuracy 91.2% (reference-adjusted), yet clarification fell 5 → 1/24; overall 57 → 55/90.
- **Copying:** copy-repair SFT fixed names but still changed `dalia.moreno.eval@...` to `dalia.moreno_eval@...`.

**Sample output (base model, task 38).** Called `modify_pending_order_payment(order_id="#W0000000", ...)`, then wrote its own fake “success” tool response in the same turn; the environment returned `Error: Order not found`.

## 8. Cost

About 15 GPU hours in total. Probing and local evaluation ran on laptop GPUs (RTX 3050 / 3060 mobile, 6 GB). Training ran on Hugging Face Jobs (single GPU, ∼27 GiB peak reserved); individual runs were capped at 70–90 minutes and $2–3 each (e.g. continued RL $2.74 max, weighted SFT $2.14 max).

## 9. Limitations

- No measured gain on native τ² tasks; development sets are small (9–114 cases) and share retail task identities.
- Qwen is used as both data teacher and NL judge; judge agreement with humans was not measured.
- 117 training conversations keep unsupported claims in assistant prose; prose provenance is not verified by the reward.
- Grounding checks are string-based heuristics, not a semantic oracle. English only.
- Recovery is learned from five controlled corruption types; failures outside this taxonomy are not yet covered.

## 10. With more credits

**Plan.** (1) Finish the assisted-start curriculum (prefix with verified reads → finish → find-and-finish → unassisted), started from the full-trajectory SFT checkpoint-70 (val loss 0.3958). (2) Add contrastive “already supplied” controls to stop unnecessary questions. (3) Build the closed self-healing loop below. (4) Evaluate on all 40 test tasks with multiple seeds and bootstrap CIs.

**Expected.** Nonzero native τ² retail success on easy tasks (cancel, return, address change) and fewer repeated failed calls; we do not have a reliable forecast for hard multi-order tasks.

> **A closed self-healing loop.** Deploy the agent behind a lightweight verifier that flags failing calls (malformed, unknown tool, schema error, ungrounded ID, policy breach, repeated failure) and classifies each one with the same taxonomy as our recovery data. The agent gets the specific error and one chance to repair. Every verified failure → error → repair becomes a new recovery example, unrepaired failures become RL scenarios in the short-goal bank, and a retrained checkpoint is promoted only if it beats the current one on the fixed 114-case set and native τ² test tasks. The agent then improves from its own production mistakes, with no new human labels.

## 12. Discussion

Local, verifiable decisions (look up by email, ask for a missing ZIP, use the reply) can be learned from a few hundred examples or a few RL updates on a small model. Turning them into end-to-end task completion is the hard part: each stage that improved one behavior often hurt another, and positive per-call rewards are easy to game. Outcome-only rewards, a curriculum that shortens the remaining horizon, and a closed self-healing loop that turns deployment failures into new training data are our next steps.
